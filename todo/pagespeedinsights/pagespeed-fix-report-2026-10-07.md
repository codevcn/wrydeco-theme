# WRYDECO PageSpeed Fix Report

Date: 2026-10-07  
Scope: P0 through P2 from the mobile PageSpeed/Lighthouse review of `https://wrydeco.com/`.

## Executive summary

The safe theme-level fixes are implemented locally. The changes remove the known font 404 paths, make the LCP hero and major homepage images responsive, resize the video poster through Shopify CDN, defer the centralized API service, reduce initial hover-gallery DOM/image work, reduce layout reads during scroll, and resolve the audited accessibility issues.

No slider scrolling behavior, product/cart/consultation business logic, `.shopify-section` behavior, or existing responsive media-query rules were changed.

One production-side action remains because the available Admin API token belongs to the development store, not the production store:

1. Deploy this theme revision to production and rerun PageSpeed against `wrydeco.com`.

## Store identity and configuration safety

- Production storefront: `wrydeco.com` → `236qm8-w7.myshopify.com`.
- Store reachable with `admin/.env` token: `wrydeco.myshopify.com`.
- The token was used only for a read-only shop identity check. It was not used to mutate production because it cannot authorize production.
- `config/settings_data.json` disables Shopify Forms for this theme revision, and the production follow-up measurement confirmed that Shopify Forms no longer appears in the live unused-JavaScript table.

## Production follow-up measurement

PageSpeed mobile was rerun in Chrome after the first production deployment:

- Original report: Performance 52, FCP 4.5 s, LCP 17.6 s, TBT 320 ms, Speed Index 7.7 s.
- New exact-URL reports: Performance 51 and 48, FCP 5.4 s, LCP 14.3–14.5 s, TBT 320–420 ms, Speed Index 7.8 s.
- Independent cache-busted homepage report: Performance 72, FCP 2.3 s, LCP 6.9 s, TBT 140 ms, Speed Index 3.3 s.
- Accessibility improved from 97 to 100; Best Practices improved from 88 to 92.
- Estimated image waste fell from 772 KiB to 109–147 KiB.
- Estimated unused JavaScript fell from 393 KiB to 169 KiB; Shopify Forms no longer appeared in the unused-JS table.
- Total network payload fell from 4,107 KiB to approximately 3,493–3,612 KiB.
- Render-blocking opportunity fell from 770 ms to approximately 450–580 ms.

The headline lab score remained highly variable because LCP, TBT, CDN timing, and third-party execution varied substantially between runs. The CSS split and second forced-reflow fix documented below were implemented after these measurements and therefore require another production deployment before their PageSpeed impact can be measured.

### P0.4 — Third-party JavaScript: partially completed; production actions documented

Shopify Forms:

- Disabled in local `config/settings_data.json`.
- Confirmed the local preview no longer requests Shopify Forms scripts.
- Production still requires the manual action listed below because the token is for another store.

Loox:

- Kept the Loox Core Script enabled.
- Confirmed the only Loox widget block in the repository is in `templates/product.json`.
- There is no Loox widget block on `templates/index.json`.
- Loox documents that widgets are page-aware, but its Core Script is a global app embed required for widgets. Loox does not document a supported “Core Script only on product templates” switch.
- Result: product reviews remain functional; the homepage receives only the small asynchronous core loader.

References:

- https://help.loox.io/support/solutions/articles/501000162390-does-loox-slow-down-your-store-
- https://help.loox.io/support/solutions/articles/501000162470-activating-the-loox-core-script-on-your-theme

Wishlist by Square / Vitals runtime:

- The production app list identifies the installed app as **Wishlist by Square**. There is no separately installed app named Vitals.
- The earlier audit called it “Vitals” because its storefront runtime uses `cdn-sf.vitals.app`, `Vtl-*` classes, and `vitals:*` events. That runtime/vendor identifier is not the Shopify Admin app name.
- Kept Wishlist by Square because Wishlist is actively used by the header/product cards.
- Did not alter the business behavior of wishlist buttons.
- Its third-party bundle cannot be tree-shaken from theme code. Reducing it further would require a supported page-scoped/lazy-loading option from Wishlist by Square, replacing the app, or removing it.
- Because the requirement is to keep Wishlist, no production configuration change is prescribed here.

Omega/Meta Pixel, Omega-provided jQuery, Shopify Chat, and the remaining requested integrations were intentionally left enabled.

### P1.6 — Render-blocking compiled CSS: completed with approved page-conditional exception

Cause:

- Shopify combines every component `{% stylesheet %}` block into the global `compiled_assets/styles.css`, including CSS for templates that are not being displayed.
- Lighthouse consequently found about 55 KiB unused on the homepage even though much of that CSS was valid on product, collection, search, customization, blog, and content pages.
- Deleting the rules would have broken those templates; the correct fix was to change when they are emitted.

Approved implementation:

- Added the user-approved exception to the normal `{% stylesheet %}` convention for page-specific components.
- Kept 25 global/homepage component styles in the compiled bundle: header, footer, announcement, cart drawer, homepage sections, global popups/controls, and repeatedly rendered card helpers.
- Converted 51 page-specific component stylesheet blocks to `{% style %}` so Shopify emits them only when their section/snippet is rendered.
- Covered product, collection, search, customization, blog/article, About, FAQ, Contact, Care Guide, list-collections, author, wishlist, generic page, and 404 components.
- Did not change any selector, declaration, responsive breakpoint, media-query rule, or visual value.
- The local generated compiled stylesheet contains 270,076 unminified characters after the split; the remaining `{% stylesheet %}` source is 269,123 characters. The 51 moved blocks are no longer part of the homepage's compiled CSS path.

The final transfer reduction must be measured after production deployment because Shopify performs the final minification, compression, and `compiled_assets` generation on its servers.

### P1.8 — Main-thread work and forced reflow: follow-up fix added after production remeasurement

Changed:

- The first production remeasurement showed that the earlier read-before-write grouping was insufficient: Lighthouse still attributed about 175 ms to Signature Pieces and 57 ms to the lead-capture scroll calculation.
- `sections/signature-pieces.liquid`: carousel geometry is now cached and remeasured only on initialization or resize. Scroll events read only `scrollLeft`; control properties are written only when their values actually change. Slider distance, smooth scrolling, drag behavior, and breakpoints are unchanged.
- `snippets/lead-capture-popup.liquid`: the document's scrollable distance is cached and refreshed by resize/`ResizeObserver`, rather than reading `scrollHeight` for every scroll event. The same percentage thresholds and popup conditions remain unchanged.

Third-party forced-reflow work inside Vitals/Omega/other app bundles cannot be edited by the theme.

Validation:

- Signature Pieces at 412px retained a 380px viewport and 3,396px scrollable track; Next moved `scrollLeft` from 0 to 284.
- Lead capture remained hidden initially and opened at the existing 40% mobile scroll threshold after its cached scroll metrics were refreshed.
- JavaScript extracted from both changed `{% javascript %}` blocks passed syntax parsing.
- Wishlist by Square reflow remains intentionally deferred for a later app-level decision.

### P1.9 — Homepage DOM size: materially reduced, but still above Lighthouse guidance

Changed `sections/signature-pieces.liquid`:

- The 48 secondary hover images are now stored inside inert `<template>` elements.
- They are cloned and requested only when their gallery is within 300px of the viewport, or immediately on hover.
- The existing cross-fade timing and hover behavior are unchanged.

Validation:

- Initial state: 12 product images and 12 inert templates.
- Near viewport/hover: each product gallery hydrates to its original maximum of five images.
- Slider navigation still changed `scrollLeft` correctly at mobile width.
- Local homepage preview measured 2,096 live elements. This is lower than the previously observed injected live DOM (~2,196) but still above Lighthouse’s general guidance.

Further DOM reduction would require a larger header/mega-menu and homepage markup redesign. That was not attempted because it would risk navigation/business behavior and responsive layout rules.
